# 2026-08-13

## Session — retirement preflight, Redis repair path, ranking reconciliation (v5.13.2)

Second external review round on `bugs/2026/08/plastic-bag-count`. Four findings assessed against the code; all four held in mechanism, one with a different consequence than reported.

- `olm:migrate-tag` refuses before any mutation when the surviving object is missing or itself retired. `--verify` already asserted this, but only after apply had reported success and cleared its snapshot; a missing survivor previously died on an uncaught FK violation inside `closePicker`.
- Apply pings Redis before closing the picker. `RedisMetricsCollector` logs and swallows every Redis error, so a run against a degraded Redis moved MySQL while discarding the matching metrics writes — which `MetricsService` never produces again once `processed_fp` has advanced.
- New `--repair-redis`: rewrites both objects' counts from MySQL, absolutely, at every location scope and contributing user hash. Bounded and complete because the objects dimension is a retirement's entire Redis footprint — the category, quantities and XP weighting are all held equal, so litter and XP deltas are zero and no stats hash, HLL or leaderboard ZSET is written. Zero is written as absence (`HDEL`/`ZREM`), keeping dead keys out of the ranking ZSET.
- Reconciliation now covers the `rank:objects` ZSETs at all four scopes, not just the `:obj` hashes. `RedisMetricsCollector::updateTags()` writes both, `LocationService::getTopTags()` reads the ZSET as its fast path, and §6 of the design doc has required it since 2026-08-08.
- A mismatch now points the operator at `--repair-redis` instead of `olm:redis:rebuild`, which §8a records as lossy for litter and unsafe on production.
- `dropRetiredPivot()` counts and deletes inside one transaction holding the pivot row's write lock. `photo_tags.category_litter_object_id` is `ON DELETE CASCADE`, so a row inserted between the count and the delete would have been destroyed by it.
- Scope enumeration shared between the two reconcilers instead of duplicated; lock acquisition shared between `--apply` and `--repair-redis`.
- Docs: `--verify`'s check list corrected from five to the ten it actually runs, §9 question 0 (null-user `TypeError`) marked resolved with its test reference, and the production runbook gains the write-freeze precondition, the repair step and the 10-minute locations-cache caveat.

Tests: `MigrateTagTest` 47 → 54. Rehearsal hashes from 2026-08-09 remain void.
