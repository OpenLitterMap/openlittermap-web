# 2026-08-14

## Session — tag retirement tooling and derived CLO (v5.14.0)

- Photo tags derive their category/object pairing from `category_id` + `litter_object_id`; the CLO pointer column is deprecated and no longer read.
- Added `olm:migrate-tag` to retire one tag key into an approved survivor, with `--type` splits and `--category` moves; dry run validates everything the apply does.
- Retired pairings record their survivor and approved subtype; stale clients and saved quick tags are rewritten onto them, following chains to the end.
- Picker, tag search and top-tags suggestions omit retired objects and retired pairings.
- `olm:verify-tag-integrity` is the deployment gate: pivot-less pairings, stale pointers, invalid types, rows or presets left on retired pairings, chain cycles; non-zero exit while anything remains.
- Declared `marine` pairings for straw, balloon, bag, bottle, lighters and the new `medium_plastic`; `industrial/plastic`; `other/random_litter`. Tag keys are snake_case singular; old keys are retired, never renamed.
- Metrics no longer write user rows for ownerless photos.
- Removed the `olm:fix-orphaned-tags` command.

- Invalid tag/category saves return validation errors instead of silently reclassifying observations.
- Web, admin and facilitator editors preserve the recorded category in object-format requests.
- Category inference ignores retired pairings for active objects while preserving retired-object redirects.

- Teacher edits preserve materials, brands, custom tags and standalone tags.
- Invalid extra-tag payloads return validation errors without removing existing tags.
- Object-format saves and quick tags validate subtypes against the final replacement pairing.
- Completed mappings can be replayed after earlier category moves and later object retirements.

**Editing impact:** After deployment, photos cannot be re-saved with undeclared pairings unchanged. Rejected saves preserve existing data. Apply the affected approved mappings before reopening, or explicitly accept temporary edit restrictions during staged cleanup. Each mapping can still run separately; no automatic data cleanup occurs.

**Migrations (automatic on deploy):** `litter_objects.retired_at` + `merged_into_id`; `category_litter_object.merged_into_clo_id` + `merged_into_type_id`. Hot paths read these columns, so deploy under maintenance mode and migrate before traffic resumes.

**Separate steps:** run the tags seeder (`composer seed:tags`) after migrating so every declared pairing exists, then apply the approved mappings one at a time under a tag-write freeze. **No production data has moved yet.** Runbook: `readme/PostTagMigrationClean.md`.
